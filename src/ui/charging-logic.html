Threshold rules, dispatcher decisions, preemption logic, and en-route resolution
Energy thresholds
Critical ≤30%
Good 50%
Sufficient 80%
Full 98%
State machine — rules by threshold level
≤ 30%
Critical — highest priority. Robot disabled until Good (50%).
energyLevel.critical = 30
Charger idle No active task Immediate recharge — disable robot ▼
FMS action
Assign recharge order immediately. Set integration level to TO_BE_RESPECTED (disabled). Robot stays disabled until battery ≥ 50%.
Robot action
Navigate to nearest free charger. Begin charging. Remain disabled until battery reaches Good (50%).
Battery hits 30%→ FMS disables robot→ Charge order issued→ Robot charges to 50%→ FMS re-enables robot
Charger idle Task in progress Complete last pallet drop, then charge ▼
FMS action
Allow current drop leg to complete. Queue recharge order as next task immediately after. Do not assign any further transport orders.
Robot action
Complete the pallet drop at destination. Proceed directly to charger without returning to parking.
The running order must be marked dispensable in openTCS so the recharge order can be queued immediately after it.
Charger occupied — Good/Sufficient robot Preempt occupant, yield charger to critical robot ▼
FMS action
Withdraw charge order from the Good/Sufficient robot (50–98%). Issue a parking order to it. Assign recharge order to critical robot at highest priority.
Robot action
Good/Sufficient robot disconnects, navigates to parking. Critical robot claims charger immediately.
Do not preempt if charger is occupied by another critical robot. Queue and wait instead.
Robot-A ≤30%→ Charger: Robot-B at 60%→ Withdraw Robot-B→ Robot-B parks→ Robot-A charges to 50%
Charger occupied — Critical robot Wait — do not preempt a charging critical robot ▼
FMS action
Charger is occupied by another critical robot. Do NOT issue a withdrawal. Hold this robot at its safe position. Queue recharge order (next in priority).
Robot action
Hold at current safe location. Once the charging robot reaches 50% and releases the charger, this robot is dispatched automatically.
New transport order arrives Transport order must be refused while robot is disabled ▼
FMS action
Robot integration level is TO_BE_RESPECTED. FMS must NOT assign any transport order to this robot until battery ≥ 50%.
Robot action
Ignore the new order. Continue charging until Good level (50%) is reached.
50%
Good — robot re-enabled, fully operational. Opportunistic charging only.
energyLevel.degraded = 50
Re-enabled after critical charge Battery reaches 50% — FMS re-enables robot ▼
FMS action
Detect battery ≥ 50%. Restore integration level to TO_BE_UTILIZED. Robot is now available for task assignment. May continue charging opportunistically.
Robot action
Becomes available for tasks. If no task is immediately assigned, continues charging toward Sufficient (80%).
Charger idle No tasks in FMS Assign opportunistic charge to lowest-battery robot in 50–80% range ▼
FMS action
Poll all robot battery levels. Find robot with lowest % between 50–80%. Assign recharge order to that robot only. Robot stays enabled (TO_BE_UTILIZED) throughout.
Robot action
Selected robot navigates to charger. Remains enabled — ready to receive transport orders while charging. Charges toward 80%.
Custom dispatcher logic required. openTCS default dispatcher does not rank by battery within the degraded range. Implement a periodic polling script or custom vehicle selector in the charging manager service.
Charging in progress Task arrives mid-charge Disconnect and execute task ▼
FMS action
Robot is enabled — dispatcher can assign transport orders normally. Withdraw the recharge order. Assign transport order immediately.
Robot action
Disconnect from charger. Navigate to pickup point. Execute transport order.
Task arrives→ Withdraw charge order→ Robot disconnects→ Execute task
Tasks available 50–80% robots stay at parking, execute tasks normally ▼
FMS action
Assign transport orders normally. Do not route 50–80% robots to charger while tasks are available. All are fully operational.
Robot action
Wait at parking. Execute assigned tasks. Return to parking between tasks. Charger is reserved for critical use or opportunistic idle use only.
80%
Sufficiently Recharged — charging may stop. Must yield charger to critical robots.
energyLevel.sufficientlyRecharged = 80
Charging in progress No tasks Continue charging toward Full (98%) ▼
FMS action
No forced action. Robot remains at charger. Monitor continuously for task arrivals, critical preemption events, or Full threshold.
Robot action
Stay connected. Continue charging passively toward 98%. Disconnect only on preemption, task assignment, or when Full is reached.
Preemption event Another robot hits Critical — yield charger immediately ▼
FMS action
Withdraw charge order from this robot (80–98%). Issue parking order. Queue recharge order for critical robot at highest priority.
Robot action
Disconnect. Navigate to parking. After critical robot finishes, this robot may be re-dispatched to the charger if still below Full.
Robot-X hits ≤30%→ FMS checks charger→ 80–98% robot detected→ Withdraw + park→ Critical robot charges
Tasks available 80–98% robots stay at parking, execute tasks normally ▼
FMS action
Assign transport orders normally. Charger used only opportunistically — not routed here while tasks exist.
Robot action
Execute tasks from parking. Return to parking between tasks. No self-routing to charger while tasks are available.
≥ 98%
Full — disconnect and park immediately. Free the charger.
energyLevel.fullyRecharged = 98
Was charging Battery reaches 98% — disconnect and park ▼
FMS action
Charging order completes (energyLevel.fullyRecharged = 98 triggers). FMS automatically creates a parking order. Routes robot to preferred parking position (tcs:preferredParkingPosition).
Robot action
Disconnect from charger. Navigate to assigned parking position. Charger is freed for the next queued robot.
Battery = 98%→ Charge order completes→ Parking order created→ Robot disconnects→ Navigates to parking→ Charger freed
openTCS handles this automatically when reparkVehiclesOnCharge = true in the dispatcher config and energyLevel.fullyRecharged = 98 is set on the vehicle model.

Group priority overrides %. Even if the en-route robot has a lower absolute % within a higher group (e.g. 52% Good vs 28% Critical), Critical always wins.
Cross-group · Good vs Critical Critical protected — never displaced by Good or Sufficient ▼
Robot A en route at 28% Critical. Robot B just freed at 55% Good. Critical is never displaced by a higher group. Robot A keeps its charge order. Robot B waits at parking.
Robot already CHARGING En-route rule does not apply — use physical preemption instead ▼
Once a robot's state transitions to CHARGING (physically at the charger), the en-route preemption rule no longer applies. Switch to the physical preemption rules:

• Good/Sufficient/Full at charger → Critical robot can preempt
• Critical at charger → another Critical robot must queue and wait
